## 1. 项目概览

飞牛终端是围绕「飞牛 NAS（fnOS）」的一体化终端套件，由三块组成：

| 模块 | 语言/框架 | 职责 |
| --- | --- | --- |
| Windows 桌面客户端 | C++17 + Qt 6.7.2 + Qt WebEngine | 原生管理界面（仪表盘/文件/容器/用户/日志/设置）+ 内嵌飞牛网页管理后台 |
| 服务端 | Node.js ≥ 22.7（无框架，原生 `https`） | HTTPS REST API、WebSocket 日志流、SQLite 存储、证书自签 |
| Web 管理后台 | 原生 HTML / CSS / JavaScript | 浏览器访问 `https://<NAS>:59120/`，与服务端同源，零外链 |

设计目标：

- **单端口**：服务端只暴露 59120，Web 后台与 API 同源，避免跨域与额外端口。
- **强安全**：仅 TLS 1.3、Argon2id 密码哈希、令牌只存哈希、24 位权限位、CSP 无内联脚本。
- **零依赖前端**：Web 后台不使用任何 CDN / 构建工具，直接由服务端静态托管。
- **一致的视觉**：客户端与 Web 后台都提供 Win7 / Win10 / Win11 / 液态玻璃四套主题，且每套都有浅色与深色。

## 2. 技术栈与环境要求

### 2.1 客户端

| 项目 | 版本 / 说明 |
| --- | --- |
| 编译器 | MSVC 2022（Visual Studio BuildTools 即可） |
| C++ 标准 | C++17 |
| Qt | 6.7.2 `msvc2019_64`（最低 6.5） |
| Qt 模块 | Core、Gui、Widgets、Network、WebEngineCore、WebEngineWidgets |
| 构建 | CMake ≥ 3.21 + Ninja |
| 运行库 | `windeployqt` 部署后的 Qt DLL（已随包提供） |

> `CMakeLists.txt` 中 `find_package(Qt6 6.5 REQUIRED ...)`，若使用更高版本 Qt，请确保包含 WebEngine 组件。

### 2.2 服务端

| 项目 | 版本 / 说明 |
| --- | --- |
| Node.js | **≥ 22.7**（必须；Argon2id 优先使用 Node 内置 `crypto.argon2`） |
| 依赖 | `argon2`、`better-sqlite3`、`dockerode`、`ws` |
| TLS | 仅 TLS 1.3 |
| 证书 | 运行时 `gen_cert.js` 自签（需要 `openssl` 或 Git 自带 openssl） |
| 数据库 | SQLite（`better-sqlite3`，WAL 模式） |

`node_modules` 已随包提供，且 `better-sqlite3` / `argon2` 内含多平台预编译产物（linux-x64、linux-arm64、linuxmusl、win32-x64、darwin），因此**在 NAS 上无需联网编译**。

### 2.3 开发工具（可选）

- Chrome / Edge DevTools：调试客户端内嵌网页（见 15.1）。
- 7-Zip：如需更高压缩比可自行打包（本项目默认 ZIP）。
- `openssl`：手动检查证书。

```
│         │        │    ├─ DashboardPage ───────────────┼──┼──┐
│         │        │    ├─ FilesPage     ───────────────┼──┼──┤
│         │        │    ├─ DockerPage    ───────────────┼──┼──┤
│         │        │    ├─ UsersPage     ───────────────┼──┼──┤

│         └────────┴───────────────────────────────────┘  │  │
│                        ApiClient (QNetworkAccessManager) │  │
└──────────────────────────────┬───────────────────────────┘  │
                               │ HTTPS 59120 / TLS1.3          │
┌──────────────────────────────▼───────────────────────────┐  │
│  飞牛 NAS                                                 │  │
│  server.js ── auth/db/users/files/docker/ws               │  │
│      ├─ public/  (Web 管理后台)                            │  │
│      ├─ data/fnos.db (SQLite WAL)                         │  │
│      ├─ data/certs  (自签证书)                             │  │
│      ├─ data/files  (文件根)                               │  │
│      └─ Docker socket (容器管理)                           │  │
└───────────────────────────────────────────────────────────┘  │
```

要点：

- **客户端 → 59120**：所有原生页面通过 `ApiClient` 调用 REST；容器日志用 WebSocket。
- **客户端 → 5667**：`AdminPage` 内嵌飞牛自带网页管理后台，独立于 59120。
- **浏览器 → 59120**：Web 管理后台与 API 同源（静态资源 + `/api/*`）。

## 5. 快速开始

### 5.1 构建客户端

```powershell
cd client-cpp
powershell -ExecutionPolicy Bypass -File build.ps1 -Deploy
```

脚本做三件事：

1. 通过 `vcvars64.bat` 初始化 MSVC 环境；
2. `cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=<QtDir>` + `ninja`；
3. `-Deploy` 时执行 `windeployqt --release --no-translations --no-opengl-sw --webenginewidgets`。

> `build.ps1` 顶部的 `$QtDir`、`$VcVars`、`$CMake`、`$Ninja` 是绝对路径。若你的安装位置不同，改这四个变量即可；脚本在找不到 MSVC CMake/Ninja 时会回退到 PATH 中的 `cmake.exe` / `ninja.exe`。

常用参数：

| 参数 | 作用 |
| --- | --- |
| `-Clean` | 删除 `build/` 后全新构建 |
| `-Deploy` | 复制 Qt 运行库（首次或改 Qt 版本时必须执行） |

产物：`client-cpp\build\bin\FnDesktopPlus.exe`。

### 5.2 本地运行服务端

```powershell
cd server\fpk\app
npm install            # 本包已含 node_modules，可跳过
node gen_cert.js       # 生成 data/certs/cert.pem + key.pem
node server.js
```

浏览器打开 `https://127.0.0.1:59120/`，首次进入「初始化」向导创建超级管理员。

### 5.3 连接客户端

1. 启动 `FnDesktopPlus.exe`；
2. 服务器地址填 `192.168.1.100`（示例），API 端口 `59120`，管理后台端口 `5667`；
3. 输入初始化时创建的账号。

## 6. 客户端（C++ / Qt 6）

### 6.1 启动流程（`src/main.cpp`）

```text
QApplication
  ├─ 设置 AA_ShareOpenGLContexts（QWebEngine 必需，必须在 QApplication 之前）
  ├─ ApplicationName = FnDesktopPlus，DisplayName = 飞牛终端，Version = 1.2.0
  ├─ Style = Fusion，字体 = Microsoft YaHei UI 9.5pt
  ├─ AppConfig::load() + normalize()
  ├─ Theme::apply(config.uiTheme, light, accent)
  └─ 循环：
       LoginDialog.exec()
         ├─ 取消 → 退出
         └─ 成功 → new MainWindow(&api, &config) → show() → app.exec()
                     └─ logoutRequested → 关闭窗口、清空 token、回到登录框
```

关键点：

- `Qt::AA_ShareOpenGLContexts` 必须最先设置，否则 `QWebEngineView` 可能黑屏。
- 主窗口 `WA_DeleteOnClose`，退出登录通过 `QPointer` 防止野指针。
- **不在磁盘保存 token**，退出即失效（服务端仍保留 7 天有效期的令牌记录）。

### 6.2 配置（`src/core/config.h`）

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `host` | 空 | NAS 地址（IP/主机名） |
| `apiPort` | 59120 | 服务端 HTTPS 端口 |
| `adminPort` | 5667 | 飞牛网页后台端口 |
| `adminPath` | `/` | 后台路径 |
| `username` | 空 | 仅记住用户名 |
| `uiTheme` | `win11` | `win7` / `win10` / `win11` / `glass` |
| `colorMode` | `dark` | `light` / `dark` |
| `accent` | `#2f81f7` | 主题强调色 |
| `lastPage` | `admin` | 上次停留页面 |
| `downloadDir` | 空 | 下载目录 |
| `rememberUsername` | true | 是否记住用户名 |

持久化位置：`AppConfig::dataDir()`（Windows 下为 `%APPDATA%\FNOS\FnDesktopPlus`），文件 `config.ini`。

**安全约束**：`config` 中**没有** password / token 字段，新增功能时请勿添加。

### 6.3 API 客户端（`src/core/api_client.h`）

- 基于 `QNetworkAccessManager`，提供 `get/post/put/del`，统一回调：
  `void(bool ok, const QJsonObject &data, const QString &message)`。
- `login(username, password, cb)` → `POST /api/auth/login`，成功后自动保存 token 到内存。
- `ping(cb)` → `GET /api/ping`（用于探测服务器与证书指纹）。
- `download(remotePath, localFile, cb)` → `GET /api/files/download?path=`，流式写入本地文件。
- `uploadFile(localFile, remoteDir, remoteName, progress, cb)`：与 Web 后台一致的三步协议：
  1. `POST /api/files/upload?path=&name=&offset=`（body 为原始分块）；
  2. 失败可续传：先 `GET /api/files/upload/status` 查询已存在大小；
  3. `POST /api/files/upload/finish` 传 `{path,name,size}` 做最终校验。
- 证书处理：`attachCertificateHandler(reply)` 只接受**当前配置主机**的证书错误，其余一律拒绝。

### 6.4 主题系统（`src/ui/theme.h`）

```cpp
enum class Id { Win7, Win10, Win11, Glass };

struct Palette {
    bool light, glass;
    int radius, radiusSm;
    QColor window, surface, surfaceAlt, border, text, muted,
           accent, accentText, danger, success, warning,
           sidebar, sidebarText, titleBar, titleText, hover, inputBg;
    QString fontFamily;
};
```

- `Theme::palette(id, light, accentHex)` 返回完整色板；
- `Theme::styleSheet(...)` 生成全局 QSS；
- `Theme::apply(...)` 应用并刷新所有控件；
- `Theme::repolish(widget)` 在动态属性（`role`、`state` 等）变化后重新计算样式；
- `Theme::assetUrl(name, color)` 生成下拉箭头/对勾图片的 `url()`。

四套主题都有浅色/深色两套配色，避免出现「侧栏黑、内容白」的割裂。新增控件时优先使用 `role` 动态属性（如 `muted`、`card`、`danger`）而不是写死颜色。

### 6.5 页面职责

| 页面 | 文件 | 主要接口 | 说明 |
| --- | --- | --- | --- |
| 飞牛网页管理后台 | `pages/admin_page.cpp` | 无（直连 5667） | QWebEngineView + 工具栏（后退/前进/刷新/首页/清除登录）+ 地址栏 |
| 仪表盘 | `pages/dashboard_page.cpp` | `/api/system/info`、`/api/docker/containers` | CPU/内存/运行时长/容器数，定时刷新 |
| 文件管理 | `pages/files_page.cpp` | `/api/files*` | 目录浏览、上传（分块+进度）、下载、新建、重命名、删除、存储用量 |
| 容器管理 | `pages/docker_page.cpp` | `/api/docker*` + WebSocket | 列表、启停重启、详情、实时日志 |
| 用户管理 | `pages/users_page.cpp` | `/api/users*` | 增删改、重置密码、权限位勾选 |
| 操作日志 | `pages/audit_page.cpp` | `/api/audit` | 分页列表、动作/用户/IP/时间 |
| 设置 | `pages/settings_page.cpp` | `/api/auth/password` | 主题、深浅色、强调色、服务器地址、修改密码 |

导航顺序固定为：管理后台 → 仪表盘 → 文件 → 容器 → 用户 → 日志 → 设置。

### 6.6 内嵌浏览器（`AdminPage`）

- 使用 **off-the-record** `QWebEngineProfile`：
  - HTTP 缓存 = `MemoryHttpCache`；
  - Cookie = `NoPersistentCookies`；
  - 关闭应用即清除网页登录状态。
- `certificateError` 信号回调中仅对配置主机调用 `acceptCertificate()`，其余拒绝。
- 地址栏回车会规范化 URL；`gotoHome()` 打开 `https://<host>:<adminPort><adminPath>`。
- `resources/inject.js` 在页面加载完成时注入，用于统一滚动条/字体等轻量适配。
- 新窗口请求（`QWebEngineNewWindowRequest`）默认在当前视图打开，避免弹出无样式窗口。

## 7. 服务端（Node.js）

### 7.1 启动与环境变量

```bash
node server.js
```

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `FNOS_DATA_DIR` | `app/data` | 数据目录（数据库、证书、`aes.key`） |
| `FNOS_FILES_ROOT` | `<data>/files` | 文件管理根目录 |
| `FNOS_PORT` | `59120` | HTTPS 端口 |
| `FNOS_HOST` | `0.0.0.0` | 监听地址 |
| `OPENSSL_BIN` | 自动查找 | 指定 openssl 可执行文件 |
| `FNOS_NODE_BIN` | 自动查找 | `cmd/main` 中指定 Node 运行时 |

启动顺序：

1. `ensureBaseDirs()` 创建 data / files / certs；
2. `generateCertificate(false)`：证书不存在或剩余有效期 < 30 天时自动生成；
3. 创建 HTTPS Server（`minVersion/maxVersion = 'TLSv1.3'`）；
4. `wsServer.attach(server)` 挂载 WebSocket upgrade；
5. 监听端口；`EADDRINUSE` 时打印中文提示并退出；
6. `SIGINT/SIGTERM` 优雅关闭（停止接收连接、关闭数据库）。

### 7.2 自签证书（`gen_cert.js`）

- 算法：RSA 2048 / SHA-256 / 有效期 3650 天；
- `CN = os.hostname()`；
- SAN：`localhost`、`hostname`、`127.0.0.1`、本机全部 IPv4；
- 输出：`data/certs/cert.pem`、`key.pem`、`openssl.cnf`；
- 自动续期：剩余有效期 < 30 天时重新生成；
- `node gen_cert.js --force` 强制重新生成。

> 客户端首次连接会提示证书不受信任，这是自签证书的正常现象。客户端仅在主机匹配时接受。

### 7.3 认证（`auth.js` + `password.js`）

- 密码哈希：Argon2id，PHC 格式
  `$argon2id$v=19$m=32768,t=3,p=4$<salt>$<hash>`，salt 32B、输出 64B；
- 后端选择：优先 Node 内置 `crypto.argon2`（Node ≥ 22.7），否则回退 npm `argon2`，并在子进程做自检，避免原生模块崩溃拖垮主服务；
- 令牌：32 字节随机 → 64 位十六进制，**数据库只存 SHA-256**；有效期 7 天；
- 请求头：`Authorization: Bearer <64位hex>`；
- 登录限流：同一 IP + 用户名连续失败 8 次后锁定 60 秒（内存计数）；
- AES：`data/aes.key`（0600），密文格式 `v1:iv:tag:cipher`（AES-256-GCM）。

### 7.4 路由分发

`server.js` 的 `route()` 顺序：

```
/api/ping → /api/setup/* → /api/auth/* → /api/system/info → /api/audit
→ /api/users* → /api/files* → /api/docker* → 静态资源（public/）
```

所有响应带安全头：


## 8. REST API 清单

## 9. 权限位与角色

24 位整数位图，当前定义 21 位（bit 21~23 保留）。

| 权限 | 常量 | bit | 值 |
| --- | --- | --- | --- |
| 创建用户 | `USER_CREATE` | 0 | 1 |
| 删除用户 | `USER_DELETE` | 1 | 2 |
| 编辑用户 | `USER_EDIT` | 2 | 4 |
| 重置密码 | `USER_RESET_PWD` | 3 | 8 |
| 系统设置 | `SYSTEM_SETTINGS` | 4 | 16 |
| 查看日志 | `SYSTEM_AUDIT_VIEW` | 5 | 32 |
| 关机/重启 | `SYSTEM_SHUTDOWN` | 6 | 64 |
| 读取文件 | `FILE_READ` | 7 | 128 |
| 写入文件 | `FILE_WRITE` | 8 | 256 |
| 删除文件 | `FILE_DELETE` | 9 | 512 |
| 上传文件 | `FILE_UPLOAD` | 10 | 1024 |
| 下载文件 | `FILE_DOWNLOAD` | 11 | 2048 |
| 分享文件 | `FILE_SHARE` | 12 | 4096 |
| 查看容器 | `DOCKER_VIEW` | 13 | 8192 |
| 启动容器 | `DOCKER_START` | 14 | 16384 |
| 停止容器 | `DOCKER_STOP` | 15 | 32768 |
| 删除容器 | `DOCKER_DELETE` | 16 | 65536 |
| 创建容器 | `DOCKER_CREATE` | 17 | 131072 |
| 容器执行 | `DOCKER_EXEC` | 18 | 262144 |
| 查看存储 | `STORAGE_VIEW` | 19 | 524288 |
| 管理存储 | `STORAGE_MANAGE` | 20 | 1048576 |

角色：

| 角色 | 说明 | 默认权限 |
| --- | --- | --- |
| `super` | 超级管理员（唯一） | 全部位（`0xFFFFFF`），且 `hasPermission` 直接放行 |
| `admin` | 管理员 | 普通用户权限 + 用户创建/编辑/重置 + 查看日志 + 容器启停/执行 + 删除文件 |
| `user` | 普通用户 | 文件读/写/上传/下载 + 查看容器 + 查看存储 |

计算示例：`FILE_READ | FILE_WRITE | FILE_UPLOAD | FILE_DOWNLOAD | DOCKER_VIEW | STORAGE_VIEW`
= 128 + 256 + 1024 + 2048 + 8192 + 524288 = **535936**。

> 新增权限位时，同时更新 `util.js` 的 `PERMS`、`PERM_BITS`、默认权限与 Web 后台的权限勾选表。

## 10. 数据库结构

SQLite，WAL 模式，`synchronous = NORMAL`，`foreign_keys = ON`。

```sql
CREATE TABLE users (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  username      TEXT    NOT NULL UNIQUE COLLATE NOCASE,
  password_hash TEXT    NOT NULL,
  role          TEXT    NOT NULL DEFAULT 'user',
  perms         INTEGER NOT NULL DEFAULT 0,
  disabled      INTEGER NOT NULL DEFAULT 0,
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL
);

CREATE TABLE tokens (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id    INTEGER NOT NULL,
  token_hash TEXT    NOT NULL UNIQUE,
  created_at INTEGER NOT NULL,
  expires_at INTEGER NOT NULL,
  last_used  INTEGER,
  ip         TEXT,
  FOREIGN KEY (user_id) REFERENCES users (id) ON DELETE CASCADE
);

CREATE TABLE audit_logs (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id    INTEGER,
  username   TEXT,
  action     TEXT    NOT NULL,
  detail     TEXT,
  ip         TEXT,
  created_at INTEGER NOT NULL
);

CREATE TABLE settings (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);

CREATE INDEX idx_tokens_hash    ON tokens (token_hash);
CREATE INDEX idx_tokens_user    ON tokens (user_id);
CREATE INDEX idx_audit_created  ON audit_logs (created_at DESC);
```

约定：

- 时间统一为毫秒时间戳（`Date.now()`）；
- `serializeUser()` **绝不返回 `password_hash`**；
- 所有语句均为参数化 `prepare()`，禁止拼接 SQL；
- 导出/备份时包含 `fnos.db`、`fnos.db-wal`、`fnos.db-shm` 与 `aes.key`。

常见审计 `action`：`SYSTEM_INIT`、`LOGIN`、`LOGIN_FAILED`、`LOGOUT`、`PASSWORD_CHANGE`、
`USER_CREATE`、`USER_UPDATE`、`USER_DELETE`、`USER_RESET_PWD`、
`FILE_UPLOAD`、`FILE_DOWNLOAD`、`FILE_MKDIR`、`FILE_RENAME`、`FILE_DELETE`、
`DOCKER_START`、`DOCKER_STOP`、`DOCKER_RESTART`、`DOCKER_LOG_STREAM`。

## 11. WebSocket 协议

- 地址：`wss://<NAS>:59120/ws/docker/logs?token=<64hex>&id=<containerId>&tail=200`
- 鉴权：token 走查询参数（浏览器 WebSocket 无法自定义请求头）；服务端仍按哈希校验并检查 `DOCKER_VIEW`。
- `id` 必须匹配 `^[A-Fa-f0-9][A-Fa-f0-9_.-]{5,127}$`；`tail` 限制 1~2000，默认 200。
- 心跳：服务端每 30s `ping`，收到 `pong` 视为存活，否则 `terminate()`。

消息（服务端 → 客户端）：

```json
{ "type": "start", "containerId": "...", "tty": false, "time": 1730000000000 }
{ "type": "data", "stream": "stdout", "data": "..." }
{ "type": "data", "stream": "stderr", "data": "..." }
{ "type": "end", "message": "容器日志流已结束" }
{ "type": "error", "message": "无法连接 Docker 服务，请确认 Docker 已启动" }
```

关闭码：`1000` 正常结束，`1011` 日志流出错。

升级失败时返回 HTTP 状态 + JSON：`400`（路径/容器 ID 非法）、`401`（token 无效或无权限）。

### 13.2 运行身份

`config/privilege`：

```json

  "allow-run-as-root": false

```

加入 `docker` 组即可访问 `/var/run/docker.sock`，无需 root。

### 13.3 脚本

| 脚本 | 行为 |
| --- | --- |
| `cmd/install` | 创建 `var/data`、`var/data/files`（700）；校验 `server.js`、`node_modules`；检测 Node ≥ 22.7 |
| `cmd/main start` | 检测 pid → 检测 Node → 导出环境变量 → `exec node server.js`（日志写 `var/app.log`） |
| `cmd/main stop` | `SIGTERM`，最多等 10s，超时 `SIGKILL` |
| `cmd/main status` | 存活返回 0，否则返回 3（fnOS 约定） |
| `cmd/uninstall` | 停止进程，保留 `var/data` |

Node 查找顺序：

```
$FNOS_NODE_BIN → <pkg>/runtime/node → PATH → /usr/bin → /usr/local/bin
→ /opt/bin → /vol1/@appcenter/nodejs/bin → /vol1/@appcenter/node/bin
```

### 13.4 把源码打成 FPK

FPK 本质是包含 `manifest`、`cmd/`、`config/`、`app/` 的压缩包。要点：

1. 保持目录层级不变；
2. `cmd/*`、`cmd/install` 必须有可执行权限（`chmod +x`）；
3. `app/node_modules` 必须随包（否则断网无法安装）；
4. **不要**打包 `app/data/`（含真实账号/证书/文件）；
5. 归档时使用 `tar`，避免 Windows 的 `\` 路径与权限丢失：

```bash
cd server/fpk
tar -czf ../fnos-terminal-1.0.0.fpk manifest cmd config app
```

## 14. 安全设计

| 面 | 措施 |
| --- | --- |
| 传输 | 仅 TLS 1.3；自签证书；HSTS 可由反代补充 |
| 密码 | Argon2id（N=2^15, t=3, p=4, salt 32B, out 64B）；密码策略 ≥8 位且含字母+数字 |
| 令牌 | 32 字节随机；库中仅存 SHA-256；7 天过期；修改密码后全部失效 |
| 暴力破解 | 同 IP+用户名 8 次失败锁定 60 秒 |
| 权限 | 24 位权限位；非 super 只能授予自己拥有的位；super 直接放行 |
| 路径穿越 | `safeResolve()` 拒绝 `..` 与越界；`safeName()` 拒绝分隔符/控制字符/Windows 保留名 |
| 注入 | 全部 SQL 参数化；静态资源使用 `safeResolve(PUBLIC_DIR, ...)` |
| XSS | CSP `script-src 'self'`；前端不使用 `innerHTML` 拼接不可信内容 |
| 点击劫持 | `X-Frame-Options: DENY` + `frame-ancestors 'none'` |
| 敏感信息 | API 不返回密码哈希；客户端不落盘 token；日志不含密码 |
| 数据加密 | AES-256-GCM，密钥 `data/aes.key` 0600 |

**开发红线**：

1. 不把账号、密码、真实 IP 写进源码或文档；
2. 不新增内联脚本（CSP 会直接拦截）；
3. 不吞异常——每个 `catch` 必须有中文日志或用户可见提示；
4. 新增路由必须显式做权限校验。

## 16. 已知限制

1. **客户端仅支持 Windows**：`build.ps1`、`app.ico`、`nativeEvent` 的标题栏拖拽均为 Win32 实现；移植 Linux/macOS 需替换标题栏与构建脚本。
2. **服务端仅 TLS 1.3**：老设备/老 curl 可能无法连接；如需兼容，可在反代层终止 TLS。
3. **自签证书**：浏览器与系统首次访问会告警；客户端做了「仅信任配置主机」的例外处理。
4. **Docker 管理依赖 socket 权限**：运行时用户必须在 `docker` 组（`config/privilege` 已配置）。
5. **文件上传为顺序分块**：不支持多连接并行分块；大文件依赖单流速度。
6. **登录限流为内存计数**：进程重启后清零；多实例部署需改为共享存储。
7. **`cmd/install` 的提示文案端口写成了 59110**：不影响实际运行（以 `manifest`/`FNOS_PORT` 为准），可顺手修正。
8. **客户端 `build/bin` 已包含 Qt DLL**：体积较大（约 230MB），但解压即可运行；如需精简可自行裁剪未用插件。

## 17. 二次开发建议

### 17.1 新增一个客户端页面

1. 在 `src/ui/pages/` 新建 `xxx_page.h/.cpp`，继承 `BasePage`；
2. 在 `CMakeLists.txt` 的 `APP_SOURCES` / `APP_HEADERS` 加入文件；
3. 在 `main_window.h` 增加成员与前向声明；
4. 在 `main_window.cpp` 的 `buildPages()` 中 `new` 并 `addWidget`，在 `buildSidebar()` 增加导航项；
5. 颜色只用 `Theme::Palette` 或 `role` 属性，确保四主题一致。

### 17.2 新增一个 API

1. 在对应模块（`files.js` / `docker.js` / `users.js`）的 `handle()` 中注册路径；
2. 第一行做 `auth.requirePermission(...)`；
3. 输入统一用 `readJson()` / `safeName()` / `safeResolve()`；
4. 输出用 `sendJson()`，错误用 `sendError()` 并给稳定 `code`；
5. 有副作用时调用 `audit()`；
6. 同步更新本文档第 8 节。

### 17.3 新增权限位

1. `util.js`：`PERMS` 增加 `1 << 21`，`PERM_BITS` 保持 24；
2. 更新 `DEFAULT_USER_PERMS` / `DEFAULT_ADMIN_PERMS`（按需）；
3. `users.js` 的 `permissionCatalog()` 增加条目（Web 后台勾选表自动读取）；
4. 在路由中使用新权限位。

### 17.4 新增 Web 后台页面

1. `index.html` 增加 `<section data-view="xxx">`；
2. `app.js` 增加路由分支、渲染函数与 API 调用；
3. `style.css` 使用现有 CSS 变量，不要硬编码颜色；
4. 确保在 4 主题 × 2 模式 × 移动端下都自查一遍。

### 17.5 代码风格

- C++：4 空格缩进，成员 `m_` 前缀，`QStringLiteral` 包裹字面量；
- JS：`'use strict'`，`const/let`，2 空格缩进，异步统一 `async/await`；
- 注释用中文，说明「为什么」而不是「做了什么」；
- 不引入新依赖，除非确有必要并说明理由。

## 18. FAQ

**Q1：客户端启动后网页区域黑屏？**
A：确认 `main.cpp` 中 `AA_ShareOpenGLContexts` 在 `QApplication` 之前设置；确认 `build/bin` 下存在 `QtWebEngineProcess.exe` 与 `resources/`。

**Q2：登录提示「用户名或密码错误」，但密码确定没错？**
A：检查服务端日志 `var/app.log`；确认 Node 版本 ≥ 22.7（Argon2 后端不匹配会导致校验始终失败）；必要时用管理接口重置密码。

**Q3：`EADDRINUSE`？**
A：端口被占用。用 `FNOS_PORT=59121 node server.js` 换端口，或结束旧进程。

**Q4：Docker 页面报 503？**
A：确认 Docker 已启动、`/var/run/docker.sock` 存在、运行用户在 `docker` 组。

**Q5：浏览器访问 59120 显示证书错误？**
A：自签证书正常现象，选择「继续访问」即可。客户端已自动处理（仅限配置主机）。

**Q6：上传大文件中断后如何续传？**
A：先 `GET /api/files/upload/status?path=&name=` 拿到 `size`，再以该值作为 `offset` 继续 `POST /api/files/upload`。若返回 `OFFSET_MISMATCH`，说明服务端文件已被改变，需要重新上传。

**Q7：主题切换后部分控件还是旧颜色？**
A：动态属性变化后需要 `Theme::repolish(widget)`；新控件应使用 `role` 属性而非硬编码颜色。

**Q8：Web 后台脚本不执行？**
A：CSP 禁止内联脚本。把代码放进 `app.js`，事件用 `addEventListener` 绑定。

**Q9：如何备份数据？**
A：停止服务后复制整个 `var/data/`（含 `fnos.db*`、`aes.key`、`certs/`、`files/`）。

**Q10：如何修改默认端口？**
A：改 `manifest` 的 `service_port`，并在启动时设置 `FNOS_PORT`；客户端「设置」页同步修改 API 端口。
